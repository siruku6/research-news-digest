## VLA (Vision-Language-Action) 関連ニュース — 2026-10-18

- **「ロボットが何を訊くか」を設計する2本 — SPEAR と Asking Smarter Questions**（分類: 論文, 2026-10-15）
  - 共通の構図は、**報酬や選好を外部のオラクル（VLM または人間）に問い合わせる際、質問の中身が未設計のまま放置されてきた**こと。問い合わせ先は違うが、どちらも「訊き方を変えるだけで効率が跳ねる」と主張する
  - **SPEAR** は VLM を選好ラベル付け役に使う構成の実用上の壁を2つ挙げる。①1クエリごとに無視できない推論コスト ②**視覚的に紛らわしい比較で VLM が回答を棄権する**。対策は、区別可能で情報量のある比較だけを選ぶ query selection と、VLM 由来のガイダンスで探索を立ち上げてから選好ベースの精緻化へ移る adaptive reward transition。平均成功率 **88.9%**（ベースライン比 **+23.3pt**）、棄権率と実時間学習時間をともに削減。実機 Mobile ALOHA の3タスクを**完全オンラインで**学習し、手作業の報酬設計を不要にする
  - **Asking Smarter Questions** は相手が人間の側。人間は一度に注意を向けられる範囲が限られるため、教示は**特徴ごとに supervision の濃さが偏る**。先行研究はその偏りを教示データから同定できたが、解決策が「もう一度教え直してもらう」で、**うまく伝えられなかった当人に負担を戻していた**点を問題視する
  - 肝は「**何を分かっていないかを示す情報が、そのまま良い質問の作り方を教える**」という読み替えで、①解消が必要な特徴に選好クエリを向ける informed prior ②**その特徴に人間の注意を向ける説明を各クエリに添える**、の2段。シミュで低クエリ域（人の労力削減が最も効く領域）で標準的な能動選好学習比 **最大 +30.8%**、ユーザ研究では prior と説明が**各々有意に効き、互いを増幅する**
  - 10/16 掲載の When to Ask for Help が「**dual-system VLA の内部で遅い側をいつ呼ぶか**」だったのに対し、こちらは**外部のオラクルに何を訊くか**という別方向の「問い合わせ設計」
  - 出典: [arXiv:2610.21621](https://arxiv.org/abs/2610.21621), [arXiv:2610.22285](https://arxiv.org/abs/2610.22285)

- **Evo-DexBench: 「関連タスクからの転移」と「タスクの丸暗記」を切り分ける**（分類: 論文, 2026-10-15）
  - 既存ベンチの欠陥を2点指摘する。**目標タスクのデモを与えすぎる**ことと、**ソースとターゲットの差が統制されていない**こと。結果として、知識転移が起きたのか単に覚えただけなのかを区別できない
  - 提案する Core-Gen 原則は、機能的な相互作用を共有する関連タスク群を Core（知識の供給源）、同じ機能ファミリ内でデモが数本しかない新規タスクを Gen（転移先）と置き、**関連度と露出量の両方を設計変数として固定する**。6つの機能ファミリ・30タスク、VR 遠隔操作で収集、**123 taxel の触覚付きシミュ Shadow Hand** で各タスク3シーン・計 1,248 件のマルチモーダルデモ
  - 結果は厳しく、**最良手法でも平均成功率 38.5%**。さらに実務的な知見として、**Core で事前学習してから Gen でファインチューンするより、Core+Gen を同時学習する方が良い**（2タスクでそれぞれ +12% / +38%）。機能的に噛み合う Core データほど利得が大きい
  - 10/14 掲載の RoboCombine が「既知スキルの**未知の組み合わせ**」、10/15 掲載の Field Guide が「手元の軌跡に**どの適応手法を選ぶか**」だったのに対し、こちらは**関連タスク間での学習順序とデータの噛み合わせ**という軸
  - 出典: [arXiv:2610.21180](https://arxiv.org/abs/2610.21180)

- **Comfortably Stuck: 「快適さ」を測っていたつもりが、止まっている時間を測っていた**（分類: 論文, 2026-10-15）
  - 閉ループ評価は開ループより忠実とされ、CARLA 上の **Bench2Drive** が事実上の標準になっている。本稿の主張は、**評価プロトコル自体に欠陥があり、採点されたモデル像が歪む**というもの
  - 中心的な数字がきれいで、nuPlan から移植した comfort 指標は実装誤りと**静止を報酬づけるセグメント分割**のせいで、8モデルにわたり**静止時間との相関が r = 0.97**。距離ベースに補正すると **r = 0.06** まで落ちる
  - 補正後、元の指標が報告していた「走行スコアと快適さの強いトレードオフ」は**走行速度を揃えて比べると検出できなくなる**。つまり快適さが拮抗していたのは「どれだけうまく走るか」ではなく「**どれだけ速く走るか**」だった
  - ハーネス側の落とし穴も2つ指摘する。①**デフォルトのコントローラがモデル自身の操舵を、経路の目標点へ向かう角度で上書きしうる** ②評価時に与えられる目標点が**学習時に見たものと大きく異なりうる**。UniAD と VAD で影響の出方が鋭く異なることを示し、修正コードを単体で公開予定（閉ループ再実行なしに記録軌跡から補正スコアを得られる）
  - 10/15 掲載の LIBERO-RIG が「**ロボット側の構成を摂動して**ポリシーの脆さを測る」だったのに対し、こちらは**測定器そのものの校正ずれ**を扱っている
  - 出典: [arXiv:2610.21741](https://arxiv.org/abs/2610.21741)

- **Unitree UniUni: 自然言語が届くのは制御ループではなく「振付レイヤ」**（分類: 製品, 2026-10-16 発表 / 10-17 報道）
  - 複数台のロボットによる演目を編成するための制御システム。**LiDAR による cm 級のステージマッピング**、ロボットごとのタイムライン編集、組み込みのアクションライブラリ、バッテリ残量・温度・緊急停止を映すリアルタイム監視、そして**自然言語での振付変更指示**を組み合わせる
  - VLA 文脈での位置づけがはっきりしていて、言語が入るのは**編成・スケジューリングの層**であり、行動生成の内側ではない。**「swarm」と称しつつ実体は自律協調ではなく、オペレータ管理下の振付**である点も報道側が明記している
  - 留保は多い。価格・提供時期・対応機種・**同時制御可能な台数の上限はいずれも非公開**で、公開されたのは販促動画であって独立した信頼性試験ではない。自然言語機能を支えるモデルも、その安全検証の手順も説明がない
  - 10/12 掲載の EASG（VLM をそのまま行動モデルにする）や 10/17 掲載の AA-Robotics（モデルに直接 API を叩かせる）と並べると、**言語をどの層まで降ろすかの選択肢**として対置できる
  - 出典: [Humanoids Daily](https://www.humanoidsdaily.com/news/unitree-uniuni-robot-swarm-choreography-control), [Robotic Gizmos](https://www.roboticgizmos.com/uniuni/)

- **「難しいのは身体ではなく脳」— OpenAI がヒューマノイド参入を明言、中国では脳側スタートアップに資金**（分類: 業界動向, 2026-10-15〜17）
  - Altman 氏は Fortune の取材で、ヒューマノイドを作るのかという問いに「**やる**」と明言。要点は**ロボットを動かす「脳」の方が外形の詳細より重要**という主張で、人型を採る理由は「世界が人間向けに設計されている」こと（扉・キーボード・工具）。**2027年にデモ**は見込むが、路上を歩くのはもっと先と留保。デモの中身・外形・社外公開時期はいずれも非開示で、アクチュエータ技術者の採用が進む段階
  - 同じ週、中国の Ruoyu（2023年創業、ハルビン工業大学・深圳キャンパス発）が **Sunway Communication 主導で9桁人民元規模の Pre-A** を完了（10/16 報道）。同社の「**九天**」ロボット脳は**クラウド側の計画とローカル側の知覚・制御を分担させる**構成で、最初の商用応用は**ロボットによる給油**。仏山のガソリンスタンドで防爆仕様を試験済み
  - 並べると構図が見える。**汎用の脳から入る側（OpenAI）と、限定ドメインで実運用データを取りに行く側（Ruoyu）**で賭け方が逆であり、後者の「クラウド計画＋ローカル制御」は 10/13 掲載の AWS Physical AI Toolchain が示した分割と同じ設計思想にあたる
  - 出典: [Engadget](https://www.engadget.com/2285040/openai-humanoid-robot-sam-altman-statement-real-challenge/), [TechNode](https://technode.com/2026/10/16/robot-ai-developer-ruoyu-secures-pre-a-funding-led-by-sunway-communication)

その他、単体では新規性のある **Procedural Assistance Memory**（「頼まれる前に助ける」先回りロボット。有限状態機械として構造化した手順記憶を VLM のタスク予測器が観測と併せて読み、VLA 実行器が実行。**再学習なしに相互作用ログから日次で記憶を更新**し、5日間の机上支援で応答時間 約5秒 → 1秒、ルーチン変更時も記憶の1回更新で復帰, [arXiv:2610.21211](https://arxiv.org/abs/2610.21211)）、**Sub-Millisecond Reflexes**（ROS 2 制御が stop-to-switch 方式のため制御モード切替が実行を中断する問題。ロックフリーのポインタ操作として実装し、Franka 実機で**切替遅延 0.1ms 未満（従来 ros2_control 比 4桁以上高速）**、多段操作タスクで実行時間 −3.5%・ピークジャーク 1/3 以下, [arXiv:2610.21913](https://arxiv.org/abs/2610.21913)）も候補でしたが、分量の都合で見送りました。業界側では **香港 FLAIR の embodied AI 応用ハブ開設**（10/16、九龍塘。Unitree・Galbot などに実環境試験の場を提供）、**Chery 系 AiMOGA の家庭向けヒューマノイド Mobo**（10/21 に蕪湖で初公開予定。自社 MoAgent と CheryMind 基盤モデル、22自由度）も出ています。
