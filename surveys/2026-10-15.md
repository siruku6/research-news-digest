## VLA (Vision-Language-Action) 関連ニュース — 2026-10-15

- **ハードウェア構成そのものを変数にする2本: FoveaVLA と LIBERO-RIG**（分類: 論文, 2026-10-13〜14）
  - **FoveaVLA** は手首カメラを**学習した「注視行動」で置き換える**提案。手首カメラは近接の細部は取れるがエンドエフェクタ周辺しか見えず、外部カメラは全体が見えるがポリシーに渡る解像度では操作に要る細部が落ちる、という二択を外しにいく
  - 仕組みは単純で、行動チャンクと一緒に**次のクエリで見るべき相互作用領域を予測**し、元解像度の画像からその切り出しを全体像と併せて入力する。π0.5 ベースで DROID + RoboInter 注釈により後訓練。実機4タスク群で、外部 RGB-D 1台の Single が **70.8%**、2台の Dual が **77.1%**（手首カメラ付き π0.5 は 52.1%）。素の pick-and-place では同等で、妨害物・布・遠方物体で優位
  - **LIBERO-RIG** は逆方向で、タスクを固定したまま**ロボット側のハードウェアと設置条件だけを摂動**するベンチ。カメラ取付・光学・カメラ-アーム校正・アクチュエータゲイン・制御レート・自己受容感覚ノイズ・ベース姿勢・台の高さ・グリッパパッドなど11軸 × 5段階 = 210条件、VLA 9種を条件あたり500エピソードで評価
  - 結果は中段で成功率 0.932 → 0.767、最高段で **0.509**。最も効く指摘は、**視覚摂動で学習しても、カメラ画像が変わらない種類の不具合（校正ずれ・制御レート・ゲイン）には効かない**こと。10/09 の WARP-VLA / VersaCamVLA がカメラ姿勢だけを扱っていたのに対し、こちらは**画像に出ない構成差**まで含めて地図を引いている
  - 出典: [arXiv:2610.20064](https://arxiv.org/abs/2610.20064), [arXiv:2610.18843](https://arxiv.org/abs/2610.18843)

- **Robota-Embed: 「行動を含めて検索する」埋め込みを作ると、何が変わるか**（分類: 論文, 2026-10-14）
  - ロボットに有用な文脈を引くには、タスク・**実行のどの段階にいるか**・そこから続くべき継続、の3つを合わせて照合する必要がある、という問題設定。著者らの知る限り**視覚・言語・行動を同時に符号化した初の VLA 埋め込みモデル**
  - 現在状態のクエリと記録済みの将来継続の両端を predictive retrieval で整列させ、過去の継続が推論時にそのまま文脈として使える形にする。学習アンカー169万件、評価用 Robota-Embed-Bench（クエリ4,000・ギャラリー8,000）を構築。clip 単位 R@1 **47.33%**、エピソード単位 **81.77%** で、行動を持たない Gemini Embedding 2 を各 +22.09pt / +33.47pt 上回る
  - 対照実験の知見が効いていて、**行動を外すと視覚を外すより検索性能が落ちる**。検索対象としての「行動」が従来軽視されていたことを示す
  - 応用2つ。Embed2ICL は検索した経験でポリシーを条件づけ DROID-Sim 47.0% → 56.3%、LIBERO 難問集合 86.4% → 92.8%。Embed2Evolve は凍結した GPT-6 Astra の周りでタスク局所の記憶を育て、ManiSkill 5タスクで **68%**（GPT-6 Astra 直接は 24%）、かつ対抗ハーネス比で**ポリシートークンを約79.5%削減**。9/26 掲載の MemBodied が「何を記憶として保持するか」だったのに対し、こちらは**記憶を引くための表現空間の側**
  - 出典: [arXiv:2610.19495](https://arxiv.org/abs/2610.19495)

- **「どのデータを、どの手法で使うか」を実証で詰める2本: AXIS-Bench と Field Guide**（分類: 論文, 2026-10-13）
  - **AXIS-Bench** は事前学習側。デモの質をどう使うか（重み付け・フィルタ・条件づけ）を、報酬定義とラベル粒度を変えながら**自然に劣悪な人間デモ5,000件 × 目標タスク24種**で比較する
  - 知見は、質の低いデモを**捨てるより「質タグを条件として与える」方が効く**という方向で、approach-aware なエピソード条件づけが素の behavior cloning を上回る。実機実験ではシミュ事前学習が成功率 9.6% → **31.7%**
  - **Post-Training, Finetuning, and Steering** は適応側。手法は大量に提案されたが「手元の軌跡から、どれを選ぶべきか」が不明という素朴な欠落を埋める。on/off-policy、オフライン/オンライン、最適/非最適軌跡を横断して LIBERO と実機 Franka で評価
  - 結論が実務的で、①**失敗データがあるオフライン環境では critic ベースの steering が教師ありファインチューンに勝つ** ②ただし critic 学習にオフライン RL を使っても**単純な Monte-Carlo 系を上回らない** ③オンラインでは steering が方策勾配系より遥かにサンプル効率が高いが、**性能の天井は full finetuning の方が高い**。10/06 掲載のデータ拡張レシピが「何を足すか」だったのに対し、こちらは**手元にあるものをどう使い分けるか**
  - 出典: [arXiv:2610.18869](https://arxiv.org/abs/2610.18869), [arXiv:2610.19143](https://arxiv.org/abs/2610.19143)

- **Physical Intelligence、π API ベータを公開 — 学習と推論をマネージドで提供**（分類: 製品, 2026-10-13）
  - 既存のオープンソースモデル（**π0・π0-FAST・π0.5**、openpi 経由）を、自前の基盤を組まずにファインチューン・デプロイできるマネージド API として提供。**新モデルの発表ではなく、提供形態の変更**という位置づけ
  - 想定フローは、デモをアップロード → PI 側の基盤でポリシーを学習 → 実機で検証 → 失敗データを追加収集、の反復。申請フォームが**遠隔操作データ・シミュデータ・タスク成功率**と並んで推論をクラウド／ローカル／ハイブリッドのどれで回すかを訊いており、ローカル提供の有無は明示されていない
  - 提示された事例は Almond の双腕 Axol によるスペーサのバリ取り（**API での反復4日**で完了）、Actor のホイールローダによるダンプトラック積込み、Formic の梱包。ただし**価格は非開示**、アクセスは申請制でバッチ単位のオンボーディング。クラウド推論では**ネットワーク接続が一部で課題**になったと明記
  - 10/09 の Ultra が PI のモデルを使う顧客側の話だったのに対し、こちらは**モデル提供側が学習基盤そのものを商品にした**側。10/13 で触れた AWS Physical AI Toolchain と同じ「ロボット学習のクラウド化」だが、こちらは自社モデルに閉じた垂直統合型
  - 出典: [Humanoids Daily](https://www.humanoidsdaily.com/news/physical-intelligence-api-beta-robot-training-inference)

その他、単体では新規性のある **Coordi-π**（双腕器用操作で、既存手法が左右の腕-ハンド行動を各時刻で単に連結し**交差相互作用を1本の行動ベクトル内に埋没させている**と指摘。左右を個別トークンにして交互列へ並べ、hand-identity 埋め込みと factorized RoPE で同時刻の左右が時間座標を共有しつつ別位置を保つ。DexJoCo 5タスクで π0.5 比 31.9% → **51.3%**, [arXiv:2610.19753](https://arxiv.org/abs/2610.19753)）、**ForceBench**（6軸手首力の統合設計を8タスク・1,600デモで横並び比較。Prompt Fusion が平均 **35.31%**（ベースライン 23.25%）。10/14 の DEFT-VLA / PRISM が「いつ効かせるか」だったのに対し**どう入れるか**の比較表, [arXiv:2610.19604](https://arxiv.org/abs/2610.19604)）、**Human Demonstrations as Post-Training Data**（スマホ収録の人間デモを**手ではなく物体の動き**でリターゲット。URDF を与えれば任意ロボットを pass / 名前付き失敗 / 拒否に**動かす前に**分類。157ペアで pass 31.2%、**拒否を無視して実行した13ペアは13件とも失敗**, [arXiv:2610.20351](https://arxiv.org/abs/2610.20351)）、**SPECTRA-VLA**（視覚エンコーダも行動デコーダも凍結したままハイパースペクトルを注入。86件の held-out でカテゴリ平衡精度 0.812 → 0.883, [arXiv:2610.19651](https://arxiv.org/abs/2610.19651)）も候補でしたが、分量の都合で見送りました。
